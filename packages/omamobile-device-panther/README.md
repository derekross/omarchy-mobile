# omamobile-device-panther

Omamobile's first userspace package for the Google Pixel 7 (codename panther, Tensor G2 / gs201). It hides the Android partitions from desktop tools, holds the USB address and brings USB back after a replug, brings up Wi-Fi with the Pixel 7 Pro's guarded start, and gives pacman the same `[omamobile]` repository as the Pixel 7 Pro. It boots the AoC (sound, microphones and sensors) with the Pixel 7 Pro's hang-safe start, and loads the camera drivers after the boot has settled. It sets the charger's policy, does not drive the modem, and does not mark a boot slot successful.

| Path | Installs to | What it does |
| --- | --- | --- |
| `vendor/environment.d/40-omamobile-rotation.conf` | `/usr/lib/environment.d` | `OMAMOBILE_ROTATION_HOLD=1`: Hyprland (packages/hyprland, 0002) holds the last frame across a rotation and turns the new one in as Android does. Off in the shared build until it has run on the other phones |
| `vendor/environment.d/40-omamobile-power-key.conf` | `/usr/lib/environment.d` | `OMAMOBILE_POWER_KEY_ANDROID=1`: the power key as Android's (omamobile-keys): a dark phone wakes on the press, a short press turns the panel off at once and locks behind it. Off in the shared shell until it has run on the other phones |
| `vendor/systemd/system/omamobile-speaker-protection.service.d/50-panther-default-cal.conf` | `/usr/lib/systemd/system/omamobile-speaker-protection.service.d` | `OMAMOBILE_SPK_DEFAULT_CAL=1`: a Pixel 7 with no `speaker.cal` in persist runs its speakers on the protection firmware's default calibration, as stock does (omamobile-audio 0.5.16; c9 and `verify` stay refused). A phone with `speaker.cal` still uses it; a line in `/etc/omamobile/speaker.conf` overrides it. omamobile-audio 0.5.16 or later is a dependency: now that the default overlays turn the speaker amplifiers on, its blacklist is what keeps their driver from loading on its own, unmuted and without the protection firmware |
| `vendor/udev/rules.d/10-omamobile-storage.rules` | `/usr/lib/udev/rules.d` | Hides `sda` and every Android partition except `userdata` from desktop tools. Same rule as the Pixel 7 Pro. The initramfs stops its guard loop before `switch_root`; the kernel's read-only flags are what remain |
| `vendor/udev/rules.d/20-omamobile-gpu-always-on.rules` | `/usr/lib/udev/rules.d` | Keeps the Mali-G710 powered while Panthor drives it: powering its domain back up needs a secure call our kernel doesn't make yet. Same rule as the Pixel 7 Pro |
| `vendor/udev/rules.d/72-omamobile-feedbackd.rules` | `/usr/lib/udev/rules.d` | Lets feedbackd drive the CS40L26 haptics (`cs40l26_vibra`). Same rule as the Pixel 7 Pro; the driver needs the phone's own `cs40l26.wmfw` (`tools/extract-vendor-firmware -d panther`) |
| `vendor/udev/rules.d/70-omamobile-dma-heap.rules` | `/usr/lib/udev/rules.d` | Lets the video group (and the seat's user) use the general DMA-BUF heaps, which libcamera's software ISP needs in a user session. Same rule as the Pixel 7 Pro |
| `bin/omamobile-camera-start` + `vendor/systemd/system/omamobile-camera.{service,timer}` + `vendor/modprobe.d/omamobile-camera.conf` | `/usr/bin`, `/usr/lib/systemd/system` (the timer enabled by a vendor wants link), `/usr/lib/modprobe.d` | Loads the camera drivers 40 s into the boot (PMIC supplies, the three sensors and the main camera's lens, the DC-PHY and CSIS), skipping them on the next boot if a load never finished, and only when the DTB enables the camera receiver (`1a450000.csis`). The modules are blacklisted for autoload so only this guard (or a runbook) loads them. The Pixel 7 Pro's script, unit and list, with panther's CSIS and without the telephoto's `sem1215` |
| `bin/omamobile-aoc-start` + `vendor/systemd/system/omamobile-aoc.service` + `vendor/modprobe.d/omamobile-aoc.conf` | `/usr/bin`, `/usr/lib/systemd/system` (enabled by a vendor wants link), `/usr/lib/modprobe.d` | Boots the AoC (audio and sensor DSP) at boot: Trusty, GSA, the AoC rails and core, then the sound card, behind a hang marker, so a start that hangs leaves the AoC off on the next boot. Runs only on a DTB with the AoC node (`aoc-core-test`). The AoC modules are blacklisted for autoload so only this guard loads them, and `aoc_alsa_dev` gets stock's raised speaker ceiling, used only with verified protection. Same script, unit and list as the Pixel 7 Pro; the firmware is the phone's own (`tools/extract-vendor-firmware -d panther`) |
| `vendor/systemd/network/20-usb-gadget.network` | `/usr/lib/systemd/network` | Sets usb0 to 172.16.42.1/24 after handover |
| `bin/omamobile-usb-rescue`, `vendor/systemd/system/omamobile-usb-rescue.service` | `/usr/bin`, `/usr/lib/systemd/system` (enabled for `multi-user.target`) | Brings USB back after a replug: the MAX77759 opens its USB2 data switch on unplug, and with no Type-C driver nothing closes it. While VBUS is valid, puts the switch back to 0x09 on the chip's I2C bus (USI13, which the board file enables). Reads two registers and writes that one; stands aside once a Type-C driver owns the chip. Same script and unit as the Pixel 7 Pro; needs `i2c-tools` |
| `bin/omamobile-wifi-start`, `vendor/systemd/system/omamobile-wifi.service`, `vendor/modprobe.d/omamobile-wifi.conf` | `/usr/bin`, `/usr/lib/systemd/system` (enabled for `multi-user.target`), `/usr/lib/modprobe.d` | Brings up Wi-Fi (BCM4389 on PCIe) at boot: the PCIe controller, then brcmfmac, behind a hang marker, so a bring-up that hangs the phone skips Wi-Fi on the next boot (`omamobile-wifi-start --retry`). The modules are blacklisted for autoload so only this guard loads them, and the unit runs only when the DTB enables the controller. Same script, unit and drop-in as the Pixel 7 Pro. The firmware is the phone's own (`tools/extract-vendor-firmware -d panther`) |
| `bin/omamobile-wlan-mac`, `vendor/udev/rules.d/80-omamobile-wlan-mac.rules` | `/usr/bin`, `/usr/lib/udev/rules.d` | Gives the Wi-Fi link the MAC address the bootloader writes into the device tree, before NetworkManager takes it. Same as the Pixel 7 Pro |
| `vendor/systemd/logind.conf.d/10-omamobile-power-key.conf` | `/usr/lib/systemd/logind.conf.d` | A short power press does not power the phone off. Same drop-in as the Pixel 7 Pro. The long press stays the PMIC reset |
| `vendor/modprobe.d/omamobile-display.conf` | `/usr/lib/modprobe.d` | Lets `gs_dsim_cmd` send DCS packets to the panel (`allow_tx=1`), so the panel driver can set the brightness and turn the display off and on. The driver ships with sending off; brightness passed DISPLAY-PLAN gate D2 on the Pixel 7 |
| `vendor/modprobe.d/omamobile-max77759.conf` | `/usr/lib/modprobe.d` | Keeps `tcpci_maxim` (it would take over the USB-C port used for SSH), `gpio_max77759` and `nvmem_max77759` from loading; the gauge, the MFD core and the charger load at boot. Without the `pmic@66` node (linux-omamobile#259) nothing of the PMIC binds |
| `vendor/modprobe.d/omamobile-charger.conf` | `/usr/lib/modprobe.d` | The charger's policy, as on the Pixel 7 Pro: a 500 mA input without a Type-C source (`default_ilim_ua`; without it the upstream driver turns charging off at probe), and stock's temperature bands from the gauge (`temp_guard`); the gauge loads first. With the `pmic@66` node it charges to 4.45 V instead of the bootloader's 4.35 V. device/panther/BATTERY-PLAN.md gates B3.3, B3g and D1 |
| `vendor/modprobe.d/omamobile-fingerprint.conf` | `/usr/lib/modprobe.d` | Keeps `sg`, `goodix_fp` and Trusty's modules from autoloading: omamobile-fp loads the first two (the RPMB LUN, the sensor), and omamobile-aoc-start loads Trusty behind its hang marker at boot, as on the 7 Pro (device/panther/FINGERPRINT-PLAN.md). A phone that opted into the fingerprint reader by hand without the AoC overlay no longer gets Trusty after this update (the AoC start stops before it when the AoC is off): add the AoC overlay, or load it by hand with `modprobe -a trusty_core trusty_log trusty_ipc trusty_virtio` |
| `vendor/systemd/sleep.conf.d/10-omamobile.conf` | `/usr/lib/systemd/sleep.conf.d` | Suspend means suspend-to-idle: the kernel offers `deep`, but Linux has no gs201 sleep sequence, and the phone doesn't wake from it. No hibernation. Same drop-in as the Pixel 7 Pro |
| `bin/omamobile-sleep`, `vendor/systemd/system-sleep/omamobile` | `/usr/bin`, `/usr/lib/systemd/system-sleep` (a link to the script) | Unloads Wi-Fi before every suspend and reloads it through the guarded service after, unless `/etc/omamobile/wifi-keep-across-sleep` exists; after a wake that fails in the Wi-Fi device it goes back to unloading for the rest of the boot. Also logs the wake reason and restarts fprintd after a wake. Wi-Fi staying loaded across suspend hasn't run on a Pixel 7. Same script as the Pixel 7 Pro |
| `vendor/NetworkManager/conf.d/10-omamobile-usb.conf` | `/usr/lib/NetworkManager/conf.d` | Keeps NetworkManager off that link |
| `etc/omamobile-mirrorlist` | `/etc/pacman.d/omamobile-mirrorlist` | Where pacman finds the `[omamobile]` repository. Same file as the Pixel 7 Pro package |
| `omamobile-device-panther.install` | pacman hook | Adds `[omamobile]` to `pacman.conf` before `[omarchy]`, once. Same script as the Pixel 7 Pro package |
| `src/reboot-to.c` | `/usr/bin/reboot-to` | Reboot with a reason the bootloader understands. Same bytes as the Pixel 7 Pro package; the test checks. On this phone `reboot-to bootloader` does not reach fastboot yet (device/panther/NOTES.md) |
| `device.conf` | `/usr/share/omamobile/device.conf` | The descriptor, the same bytes as `device/panther/device.conf` |

`./build [DIR]` compiles `reboot-to` from this directory, `./install DESTDIR [DIR]` stages the files, and `test/all` checks the copies when it is run from the repository.

Not in this package: the boot-success marker, the modem, and the slot-B image hook. Those stay out until each one has its own runbook.
