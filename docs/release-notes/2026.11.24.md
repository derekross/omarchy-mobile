# Omamobile 2026.11.24 (developer preview)

The fourth release, and the first under the project's new name, Omamobile: native Omarchy (Arch Linux ARM, Hyprland and Omarchy's own packages) on the Google Pixel 7 Pro, with a mainline Linux kernel and no Android underneath. This is a **developer preview**: it installs and runs as an everyday Linux phone for people comfortable with fastboot, but some hardware is still being worked on (below), installing erases the phone's data, and stock Android stays on slot A as the way back.

Omamobile is an independent community project built on [Omarchy](https://omarchy.org). It is not an official Omarchy or Basecamp project, and it is not affiliated with or endorsed by Google.

## What's in it

- **Device:** Google Pixel 7 Pro (`cheetah`, Tensor G2 / gs201). No other phone is part of this release.
- **Kernel:** `kernel-2026.11.24`, linux-omamobile's `omamobile` branch at `00860bdedea4` (Linux 7.3-rc6 plus our drivers); `uname -r` is `7.3.0-rc6-omamobile-g00860bdedea4`. The source is public at that tag before any binary ships. Since `kernel-2026.11.15` it adds bring-up for other phones (among them the Pixel 7's hardware video engine, the Pixel 8a's CPU and GPU scaling and battery, and the Pixel 9a's sleep fixes); on the 7 Pro nothing changes that you would notice.
- **Userspace:** Arch Linux ARM, Omarchy 4.5.0-3 (held at that version in `[omamobile]`: it is the one our patches were checked against) with our pending patches (re-applied after every Omarchy upgrade), and the signed `[omamobile]` repository (pkgs.omamobile.org, stable channel) for the phone shell, Mesa for the Mali-G710, Hyprland, libcamera and the device support packages.
- **Updates:** `omarchy update` on the phone or the Updates entry in the app drawer, from the stable channel, kernel included: the kernel is the `linux-omamobile` package, and `omamobile-boot-update`'s pacman hook writes a new one to slot B (it never reboots by itself; the update sheet asks for a restart). In this release's test install the hook rebuilt slot B's images on the phone byte for byte the same as the bundle's.

### New since 2026.11.15

- **The project is now Omamobile.** Omarchy's author asked that the phone project not be called "Omarchy Mobile", so it isn't mistaken for an official Omarchy project. The repositories are now [derekross/omamobile](https://github.com/derekross/omamobile) and [derekross/linux-omamobile](https://github.com/derekross/linux-omamobile) (the old addresses redirect), and the name changed in the packages, the installer and the documentation. Nothing changes on a phone: package names, paths and the repository at pkgs.omamobile.org stay as they were.
- **Mobile data comes back after the network ends the IMS connection.** When the network closed the IMS (calling) bearer, the internet bearer's reconnect waited on it and data could stay down; the phone service now sets up data again on its own (`omamobile-modem-sit` 0.3.44).
- **The status bar:** a choice of battery styles and a switch for each status icon (`omamobile-shell` 0.2.144), and the unread count sits beside the clock, clear of the camera cutout (0.2.147).
- **Phone shell fixes** (`omamobile-shell` 0.2.134 to 0.2.147): the voice preview can no longer be left holding the microphone; the call card's ring no longer keeps running with no call up; recent apps stop a card's live copy before closing its window; a command started from the shell runs in its own scope, as an app does; Chromium and Grok Bot are fitted once to the panel; selecting text in the terminal also puts it on the clipboard; a Greek terminal keyboard layout; a new PIN needs at least 4 digits.
- **Omarchy fixes** (`omamobile-omarchy` 0.1.49 to 0.1.51): changing the screen timeout takes effect without a restart, and the network panel's details fit a narrow card.
- **The storage guard and kernel updates follow the slot the phone runs from** (`omamobile-device-cheetah` 0.1.61, `omamobile-boot-update` 0.2.0). On the 7 Pro that is still slot B, so nothing changes today; it prepares installs to the active slot, which no phone uses yet.
- **Waydroid without Google apps.** The optional `omamobile-waydroid` package (0.1.5, not installed by default) no longer offers to install Google's apps: Omamobile ships and documents none.
- **Release checks:** the identifier scan that every release passes before it ships now fails when a file can't be read, follows symlinks, and reads package archives file by file.

## Known issues

- **Calls, texts and mobile data work on the tested network.** Tested on the reference phone with one Verizon-network SIM (Tracfone): VoLTE calls both ways, texts over IMS, and mobile data as a fallback route behind Wi-Fi ([DEVICES](../DEVICES.md)). Other networks are untested. The SIM's APNs and bearer order come from its carrier, read once from the SIM at boot: a Verizon-network SIM is the one proven end to end; other carriers take the carrier database's APNs, and the Mobile network page under Setup shows and corrects them. After a start, the phone service takes a minute or two to register and bring up IMS; until then it shows the SIM as unknown and the radio as off. Each restart with the modem up costs one recovered storage error-handler pass. After a hang or a forced reset with the modem up, the next boot starts the modem all the same; if that boot ends the same way, the modem stays off (the Mobile data tile says "Off after a hang or reset (held)") until the markers are cleared by hand (`sudo rm -f /var/lib/omamobile/modem-up /var/lib/omamobile/modem-up.refused-*`, then restart the phone). To keep the whole stack off: `sudo systemctl mask omamobile-modem-boot.target`.
- **Sleep with the modem up:** between a dropped data connection and its reconnect, a push notification can arrive late. A phone that sleeps badly with the modem up can go back to staying awake: `sudo touch /etc/omamobile/modem-suspend-disable`, then restart. Wi-Fi traffic and a USB plug can't wake a sleeping phone.
- **Cameras:** basic image quality (no Google ISP or tuning); the telephoto doesn't focus.
- **Bluetooth:** headset calls (HFP) don't work yet.
- **USB-C:** the phone is a USB device only (no host mode or role switch yet); after a replug, `omamobile-usb-rescue` reconnects it.
- **Fingerprint starts once per boot by design:** if it stops, restart the phone. Its first start writes the phone's secure storage (Trusty's area in the RPMB, the same kind of write as an Android factory reset); `persist` and `mfg_data` are only read. Fingers are enrolled again after a reinstall. To keep it off, `sudo systemctl mask omamobile-fp`.
- **Google's firmware is not included** and never will be, and installing it is still a separate step: after the first start, run the bundle's `tools/phone-provision` with your own factory image for your phone (Wi-Fi, Bluetooth, haptics, speakers, sensors, the modem, cameras and the fingerprint sensor), then restart the phone. Until then Wi-Fi, sound, the modem and fingerprint don't work. The guided install does this step for you.
- **Installing by hand, keep the phone awake while it is set up.** The phone sleeps when its screen goes off, and a sleeping phone leaves USB, so a `tools/phone-provision` or `tools/nv-backup` run started by hand can stop halfway with "Connection timed out". Wake and unlock the phone and run it again (it starts over; nothing is half-written). The guided install holds the phone's sleep off from the first start to its check.
- **Run `omarchy update` as yourself, never as root:** from the phone's terminal or the Updates entry. As root it is refused, with the reason.
- **A completely flat battery:** if the phone keeps restarting on the cable, hold Volume Down + Power for fastboot and leave it there on the charger for 20-30 minutes (`fastboot getvar battery-voltage` should pass 3.8 V), then choose Start ([#169](https://github.com/derekross/omamobile/issues/169)).
- **Stopping the modem** (`systemctl stop omamobile-modem`) takes 40 s and is logged as a crash ([#532](https://github.com/derekross/omamobile/issues/532)), though it stops cleanly; to get the modem back, restart the phone rather than starting it again.
- **A first install from stock Android with the guided install, or with the installer app ([v0.1.0](https://github.com/derekross/omamobile-installer/releases/tag/v0.1.0)), stops at the bootloader-slots check.** On a phone that has only run stock Android, the check of slot B's bootloader against the factory image's stops the install; don't work around it, [open an issue](https://github.com/derekross/omamobile/issues) or install by hand (below). A reinstall over Omamobile goes through: the guided install asks whether the phone already runs Omamobile, and by hand it is `bash install --reinstall`.
- **`systemd-firstboot` fails once** on the first start (the phone has no console); Omamobile's own first-boot setup does its job.

## Updating from an earlier release

A phone installed from 2026.11.15, 2026.11.12 or 2026.11.08 doesn't need this image: open Updates, or run `omarchy update`, then restart when the update sheet asks. From 2026.11.08, the first update also moves the phone to Omarchy 4.5 (see [the 2026.11.12 notes](2026.11.12.md)); there is no way back to Omarchy 4.0.6 short of installing again.

## Phones running a development build

A phone installed from the repository follows the development channel and gets all of this with `omarchy update`. Its kernel stays as it is: `omamobile-boot-update` is off unless `/etc/omamobile/boot-update.conf` says `AUTO_WRITE=yes`, so slot B is still written by `bin/omamobile push`. A phone from before the release key or before Hyprland 0.57 needs the two one-time steps in [the 2026.11.08 notes](2026.11.08.md) first.

## Installing

Follow [docs/INSTALL.md](../INSTALL.md), step by step. In short: a Pixel 7 Pro with an **unlocked bootloader**, a Linux computer with `fastboot` and the tools INSTALL.md lists, and Google's factory image for `cheetah`. Download the one file `omamobile-cheetah-2026.11.24.tar` with its `.tar.sha256` (and `.tar.sha256.sig`, to check the signature) from `https://pkgs.omamobile.org/releases/cheetah/2026.11.24/`, check it with `sha256sum -c`, unpack it with `tar -xf`, then run `bash install --guided` in the unpacked folder for the guided install, or `bash install --dry-run` and `bash install` to install by hand. Installing by hand, after the first start, back up the phone's radio partitions with the bundle's `bash tools/nv-backup BACKUP-DIR` (INSTALL.md step 6; read-only, keep the backup folder private: it holds your IMEI), then add Google's firmware with `bash tools/phone-provision --first-install --nv-backup BACKUP-DIR FACTORY-IMAGE.zip` (INSTALL.md step 7).

If the installer stops about the bootloader slots on a first install, don't work around it: [open an issue](https://github.com/derekross/omamobile/issues). On a reinstall over Omamobile, add `--reinstall`: the phone already runs slot B's bootloader.

What it writes: slot B's `boot`, `init_boot`, `vendor_boot`, `vendor_kernel_boot` and `dtbo`, and `userdata` (**erased**). It never touches slot A, the bootloader, radio, `persist`, `efs`, `modem`, `devinfo` or `vbmeta`.

## Going back to stock Android

Stock Android is still on slot A. In fastboot: `fastboot --set-active=a`, then `fastboot reboot`, and factory-reset Android when it asks (its data was erased by the install). Or flash Google's factory image for `cheetah`. Before you first boot stock again, note that stock's modem stack rewrites `efs`, `persist` and `modem_userdata`; keep your read-only backup of them.
