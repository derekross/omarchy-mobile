# Omarchy Mobile 2026.11.12 (developer preview)

The second release of Omarchy Mobile, and the first built on Omarchy 4.5: native Omarchy (Arch Linux ARM, Hyprland and Omarchy's own packages) on the Google Pixel 7 Pro, with a mainline Linux kernel and no Android underneath. This is a **developer preview**: it installs and runs as an everyday Linux phone for people comfortable with fastboot, but some hardware is still being worked on (below), installing erases the phone's data, and stock Android stays on slot A as the way back.

Omarchy Mobile is a community project built on [Omarchy](https://omarchy.org). It is not an official Omarchy or Basecamp product, and it is not affiliated with or endorsed by Google.

## What's in it

- **Device:** Google Pixel 7 Pro (`cheetah`, Tensor G2 / gs201). No other phone is part of this release.
- **Kernel:** `kernel-2026.11.08`, linux-omarchy-mobile's `omamobile` branch at `1a9d1d4e9289` (Linux 7.3-rc6 plus our drivers); `uname -r` is `7.3.0-rc6-omamobile-g1a9d1d4e9289`. The source is public at that tag before any binary ships.
- **Userspace:** Arch Linux ARM, Omarchy 4.5.0-3 (held at that version in `[omamobile]`: it is the one our patches were checked against) with our 28 pending patches (re-applied after every Omarchy upgrade), and the signed `[omamobile]` repository (pkgs.omamobile.org, stable channel) for the phone shell, Mesa for the Mali-G710, Hyprland, libcamera and the device support packages.
- **Updates:** `omarchy update` on the phone or the Updates entry in the app drawer, from the stable channel, kernel included: the kernel is the `linux-omamobile` package, and `omamobile-boot-update`'s pacman hook writes a new one to slot B (it never reboots by itself; the update sheet asks for a restart). On 2026-11-12 a phone installed from release 2026.11.08 took the update to Omarchy 4.5 from its Updates sheet: the hook wrote slot B's new boot image, read it back, and the phone restarted into it. On the test install of this release, the Updates sheet then took the one package the repositories had published since the image was built.
- **Same kernel as 2026.11.08.** This release changes the userspace, not the kernel.

### New since 2026.11.08

- **Omarchy 4.5.** The image is built on Omarchy 4.5.0-3, with the patch series ported to it: the notification shade and the bar read 4.5's notification store, the Do Not Disturb tile reads 4.5's state, and double tap to wake and the About layout carry over.
- **Settings comes with the phone:** a Settings app with a device information page and a Display page (brightness and refresh rate). It was missing from fresh installs of 2026.11.08 and arrives there with the update.
- **Back goes back one level,** and home from an app's top level.
- **Location works after install.** The helper that lets apps ask for a position starts by itself; the off-and-on of the Location tile that 2026.11.08 needed is gone.
- **One unclean end no longer costs the next boot its modem.** After a hang or a forced reset with the modem up, the next boot starts the modem all the same; only a second such end in a row holds it. A restart through `reboot-to` isn't counted as an unclean end.
- **`reboot-to --help` prints its usage** instead of restarting the phone.
- **Swap on zram** at half the RAM.
- **The USB connection keeps the same addresses across boots,** so the computer's network profile for the phone keeps matching.
- **A first start without a name or email** finishes the user's setup.
- **An update as root is refused, with the reason,** instead of stopping part way (see Known issues in 2026.11.08).
- **The installer:** `install --verify-only` reads and lists the shipped ramdisk too; a work directory that can't be written, a path with a space and a run killed part way are handled and said.
- **The bundle carries `factory-builds.json`:** the list of Google factory builds for the Pixel 7 Pro and which of them a release was tested with (metadata only, none of Google's files). The coming installers read it.
- **A guided install, in the repository for now:** `tools/install-guided` runs the install, the first start, the radio backup and the firmware step as one command that resumes where it stopped. It did its first whole install on 2026-11-12. No bundle ships it yet; [docs/INSTALL-GUIDED.md](../INSTALL-GUIDED.md) describes it.

## Known issues

- **Calls, texts and mobile data work on the tested network.** Tested on the reference phone with one Verizon-network SIM (Tracfone): VoLTE calls both ways, texts over IMS, and mobile data as a fallback route behind Wi-Fi ([DEVICES](../DEVICES.md)). Other networks are untested. The SIM's APNs and bearer order come from its carrier, read once from the SIM at boot ([#373](https://github.com/derekross/omarchy-mobile/pull/373)): a Verizon-network SIM is the one proven end to end; other carriers take the carrier database's APNs, and the Mobile network page under Setup shows and corrects them. Call audio through the earpiece works at every speaker stage (`omamobile-audio` 0.5.13), on by default (`omamobile-modem-sit` 0.3.30 with `omamobile-device-cheetah` 0.1.44). A development install whose `/etc/omamobile/modem-sit.conf` was edited (the Mobile network page writes it) keeps its `card = none` line: delete it for call audio. With the modem up the phone never sleeps (the stack holds a sleep inhibitor, because suspend with the modem up isn't qualified), and each restart with the modem up costs one recovered storage error-handler pass. After a hang or a forced reset with the modem up, the next boot starts the modem all the same (`journalctl -b -1 -u omamobile-modem` has that boot's line); if that boot ends the same way, the modem stays off (the Mobile data tile says "Off after a hang or reset (held)") until the markers are cleared by hand (`sudo rm -f /var/lib/omamobile/modem-up /var/lib/omamobile/modem-up.refused-*`, then restart the phone), and a clean reboot in between resets the count. `sudo touch /etc/omamobile/modem-hold` holds it from the first time. To keep the whole stack off: `sudo systemctl mask omamobile-modem-boot.target` (`disable` doesn't remove the package's link, and `systemctl is-enabled` reads "disabled" either way).
- **Suspend: works when asked for, auto-sleep off by default.** `systemctl suspend` sleeps and wakes reliably (on a key or the RTC), Wi-Fi stays connected across it, and standby lasts about 16 hours, well short of stock's. Auto-sleep after the screen goes off ships **off**; it can be turned on with `omarchy-toggle omamobile-sleep on`, but it hasn't finished a day-long test. With the modem up the phone doesn't sleep at all (above). Wi-Fi traffic and a USB plug can't wake the phone.
- **Cameras:** basic image quality (no Google ISP or tuning); the telephoto doesn't focus.
- **Bluetooth:** headset calls (HFP) don't work yet.
- **USB-C:** the phone is a USB device only (no host mode or role switch yet); after a replug, `omamobile-usb-rescue` reconnects it.
- **Fingerprint starts once per boot by design:** if it stops, restart the phone. Its first start writes the phone's secure storage (Trusty's area in the RPMB, the same kind of write as an Android factory reset); `persist` and `mfg_data` are only read. Fingers are enrolled again after a reinstall. To keep it off, `sudo systemctl mask omamobile-fp`.
- **Google's firmware is not included** and never will be, and installing it is still a separate step: after the first start, run the bundle's `tools/phone-provision` with your own factory image for your phone (Wi-Fi, Bluetooth, haptics, speakers, sensors, the modem, cameras and the fingerprint sensor), then restart the phone. Until then Wi-Fi, sound, the modem and fingerprint don't work, and the setup can't offer a fingerprint. Installers that do this on their own are being built.
- **Run `omarchy update` as yourself, never as root:** from the phone's terminal or the Updates entry. As root it is refused, with the reason.
- **A completely flat battery:** if the phone keeps restarting on the cable, hold Volume Down + Power for fastboot and leave it there on the charger for 20-30 minutes (`fastboot getvar battery-voltage` should pass 3.8 V), then choose Start ([#169](https://github.com/derekross/omarchy-mobile/issues/169)).
- **Stopping the modem** (`systemctl stop omamobile-modem`) takes 40 s and is logged as a crash ([#532](https://github.com/derekross/omarchy-mobile/issues/532)), though it stops cleanly; to get the modem back, restart the phone rather than starting it again.
- **The logo on the setup screens sits at the left edge** rather than in the middle. `omamobile-omarchy` 0.1.45 centres it ([#717](https://github.com/derekross/omarchy-mobile/pull/717)) and arrives with an update.
- **Power off restarts the phone.** Shutdown from the power menu (or `systemctl poweroff`) shuts the phone down cleanly and it then starts again by itself, with the cable in or out. The fix is in the kernel's source ([linux-omarchy-mobile#233](https://github.com/derekross/linux-omarchy-mobile/pull/233)) and comes with the next kernel release; this release has the kernel of 2026.11.08.
- **`systemd-firstboot` fails once** on the first start (the phone has no console); Omarchy Mobile's own first-boot setup does its job.

## Updating from 2026.11.08

A phone installed from release 2026.11.08 doesn't need this image: open Updates, or run `omarchy update`. The update carries Omarchy 4.5, the phone's packages and a new boot image, takes a while, and asks for a restart at the end.

- **You may see two error lines about "temporary Omarchy sudo grants" in the update's log.** They appear once, during that update only, and changed nothing on the phone we tested.
- **There is no way back to Omarchy 4.0.6** short of installing again.

## Phones running a development build

A phone installed from the repository follows the development channel and gets all of this with `omarchy update`. Its kernel stays as it is: `omamobile-boot-update` is off unless `/etc/omamobile/boot-update.conf` says `AUTO_WRITE=yes`, so slot B is still written by `bin/omamobile push`. A phone from before the release key or before Hyprland 0.57 needs the two one-time steps in [the 2026.11.08 notes](2026.11.08.md) first.

## Installing

Follow [docs/INSTALL.md](../INSTALL.md), step by step. In short: a Pixel 7 Pro with an **unlocked bootloader**, a Linux computer with `fastboot` and the tools INSTALL.md lists, and Google's factory image for `cheetah`. Download the one file `omamobile-cheetah-2026.11.12.tar` with its `.tar.sha256` (and `.tar.sha256.sig`, to check the signature) from `https://pkgs.omamobile.org/releases/cheetah/2026.11.12/`, check it with `sha256sum -c`, unpack it with `tar -xf`, then run `bash install --dry-run` and `bash install` in the unpacked folder. After the first start, back up the phone's radio partitions with the bundle's `bash tools/nv-backup BACKUP-DIR` (INSTALL.md step 6; read-only, keep the backup folder private: it holds your IMEI), then add Google's firmware with `bash tools/phone-provision --first-install --nv-backup BACKUP-DIR FACTORY-IMAGE.zip` (INSTALL.md step 7).

If the installer stops about the bootloader slots on a first install, don't work around it: [open an issue](https://github.com/derekross/omarchy-mobile/issues). On a reinstall over Omarchy Mobile, the phone already runs slot B's bootloader, and the installer's message names the two options to add (`--reinstall` and `--bootloader-slots-match`).

What it writes: slot B's `boot`, `init_boot`, `vendor_boot`, `vendor_kernel_boot` and `dtbo`, and `userdata` (**erased**). It never touches slot A, the bootloader, radio, `persist`, `efs`, `modem`, `devinfo` or `vbmeta`.

## Going back to stock Android

Stock Android is still on slot A. In fastboot: `fastboot --set-active=a`, then `fastboot reboot`, and factory-reset Android when it asks (its data was erased by the install). Or flash Google's factory image for `cheetah`. Before you first boot stock again, note that stock's modem stack rewrites `efs`, `persist` and `modem_userdata`; keep your read-only backup of them.

## Checksums and signatures

The bundle's `SHA256SUMS` is signed with the Omarchy Mobile release key (`2056 7593 566E EEE2 DD88  6460 8632 C807 5EB9 4673`); its `MANIFEST` and `manifest.json` name the root image and its SHA-256, so the installer checks the root image against the signed record before it contacts the phone.
